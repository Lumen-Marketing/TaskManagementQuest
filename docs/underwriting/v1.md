## Architecture

MEASURE → CALCULATE → MATERIALS → COST → PROVE lives inside the existing Bid
Underwriting view/model, with one persisted underwriting per Bid. `RoofMeasurement`
is the normalized adapter boundary, not another estimator. All downstream math
extends the existing BigInt fixed-point engine.

- **MEASURE:** reviewed manual entry from a PDF, report filename/reference/date,
  summary page, roof area, facets, pitch-area distribution, geometry, reported
  accessory lengths, printed waste rows and material recommendations. Unknown
  fields stay null; explicit zeros stay zero. Per-field provenance carries source
  reference, page, label and unit. Whole source PDFs and SHA-256 checksums accompany
  the three regression fixtures. Attach live reports through the existing Bid files.
- **CALCULATE:** GAF suggested waste is retained separately from editable selected
  waste. Decimal area/squares remain migration 073's values. Whole-SF/order-square
  quantities use the printed report waste row when available, otherwise exact
  arithmetic with half-up whole-SF rounding and ceiling of exact area/100.
- **MATERIALS:** eleven starting lines, explicit product/unit, coverage rule,
  quantity, optional override, supplier, unit price and price-check date. Prices
  begin blank. A changed product requires an explicit quantity confirmation.
  Nails use imported report recommendations at the selected waste; a new waste
  without such a recommendation requires manual nail quantities. Low-slope
  quantities remain separate; areas below 2/12 use low-slope coverage. These are
  guidance quantities, not a complete code-compliance or installation specification.
- **COST:** material tax, labor per order square, named job costs, client price,
  commission and overhead. The existing calculate() receives the allocated cost
  totals and target margin, preserving 073 CHECK equations. Actual client-price
  gross/net profit and net margin are separately visible; PROVE uses net margin.
  The legacy recommended-price formula remains explicit and is not presented as
  an independent net-margin recommendation.
- **PROVE:** measurements verified, waste confirmed, takeoff reviewed, labor
  confirmed, pricing current, and actual net margin within the underwriter's
  target. Pricing current is a human confirmation backed by supplier/date evidence;
  no unapproved automatic price-expiry policy was invented. Input changes clear
  the corresponding confirmations. Review/approval use saved evidence, and existing
  approval permissions and locked-record rules remain in force.

`RoofMeasurement.registerAdapter()`/`importReport()` accept future parsers returning
this same schemaVersion 1 contract. No XML parser, GAF tag, API or schema is guessed.
V1's user intake is ordinary report fields; JSON fixtures are test/adapter data.

## Persistence and rollout

075 adds a nullable workflow JSONB column to the existing underwritings table,
allows workflow changes in existing append-only history, and adds one atomic V1
save RPC. Legacy saves retain their existing RPC. RLS, tenant tables and 073
numeric constraints are unchanged. The database guard recomputes coverage and
financial totals, checks saved source/inputs against the snapshot, invalidates
review confirmations after edits and blocks unready review/approval. History's
actor/time come from the database, not browser claims. Overrides require a reason.

**075 is unapplied and NOT database-certified.** Rehearsal attempted fresh local
PostgreSQL with network listening disabled and explicit Unix sockets. The sandbox
blocked shared-memory creation during initdb. No hosted database was contacted.
Do not deploy the V1 UI for live saves until 075 is rehearsed and reviewed in DEV.
Existing legacy saves remain usable without 075. The rollback refuses to remove
075 when a V1 record/history exists.

Before merge/deployment, verify on isolated DEV: apply 075 twice; replay 073 and
074 permission/tenant/proposal tests; save/read all three source fixtures; inspect
atomic history; reject forged quantity/cost snapshots; reject worker access and
cross-tenant writes; verify supervisor versus admin decisions; verify locked
records; verify source/cost/waste edits invalidate reviews; verify concurrent saves
and stale-version behavior. No authenticated hosted behavior is claimed here.
The existing post-save reload behavior is unchanged and can briefly show an older
record if the refresh fails; no conflict-resolution mechanism was added.
